# MindHaven 项目体检与测试报告

> 核验日期：2026-08-03
> 核验范围：仓库结构、当前实现、未提交改动、构建、后端启动、数据库迁移与接口冒烟。
> 结论边界：这是本地开发环境核验，不等同于生产验收、安全审计或完整 E2E。

## 1. 结论

项目已经不是“只有前端原型和健康检查”的骨架，而是一个可本地联调的全栈 MVP。主流程包括认证/RBAC、个人日记、AI 会话、公开知识库、文件、后台聚合、风险事件和审计。当前主要短板从“缺业务实现”转为“自动化测试、令牌生命周期、上线安全和运维工程化不足”。

建议将当前阶段定义为：**MVP 功能闭环完成，进入质量加固与上线准备阶段**。不建议直接标记为生产可用。

## 2. 项目结构

| 层级 | 技术与职责 | 当前规模/特征 |
| --- | --- | --- |
| `frontend` | Vue 3、Vite、Element Plus、Axios、ECharts、wangEditor | 11 个页面、9 个公共组件、5 个 API 模块；用户端与管理端共用 SPA |
| `backend` | Spring Boot 4.1、Java 21、Spring MVC/JPA、MySQL、Flyway | 94 个主 Java 源文件、17 个 Repository、14 个 Controller、9 个 Service |
| `backend/db/migration` | V1 基线、V2 参考数据、V3 中文情绪列、V4 阅读事件 | 启动时由 Flyway 校验，Hibernate 使用 `ddl-auto=validate` |
| `docs` | PRD、架构、API、数据模型、路线图 | 原文停留在后端骨架阶段，本次已同步更新 |

后端目前按技术层平铺，适合当前体量；下一阶段应先收紧模块依赖和测试边界，再渐进迁移为业务模块包，不需要拆微服务。

## 4. 已发现问题

### P0：上线前必须解决

- 自动化测试几乎为空，当前绿灯主要证明“能编译、能手工冒烟”，不能防止业务和权限回归。
- `logout` 不撤销令牌，`refresh` 未实现；默认 JWT 密钥和数据库密码仅适合本地环境。
- 心理安全使用本地规则适配器，只能作为演示基线；真实模型接入前必须完成输入/输出检查、固定危机指引不可覆盖、地区化热线和危机场景测试。
- 日记、会话、文件和敏感风险详情需要系统化水平越权/垂直越权测试。

### P1：近期质量加固

- 不支持的 `Content-Type` 当前被通用异常处理为 500，应映射为 415/400并加入 Controller 测试。
- 前端没有 lint/test/E2E；仍有调试日志，且构建有 3 个超过 500 kB 的 chunk，最大约 1.13 MB。
- 缺少 OpenAPI、契约生成、CI、依赖/漏洞扫描、容器化与生产 profile 基线。
- `DataInitializer` 体量和职责过大，失败时只告警且可能部分写入；建议拆成可验证的演示数据 fixture，并由事务或分阶段状态保证一致性。
- 权限查询返回重复 permission code（本次 admin 19 项中存在重复），应在查询或服务层去重。

## 5. 建议测试金字塔

1. 后端单元测试：风险规则、JWT、HTML 清洗、状态机、分页和 DTO 校验。
2. Repository/Testcontainers：Flyway 从空库升级、唯一约束、聚合查询和所有权查询。
3. MockMvc 集成测试：每个 P0 API 至少覆盖成功、400、401、403、404、409。
4. SSE 测试：UTF-8 分片、幂等、断开、超时、危机分流、空回复。
5. 前端 Vitest：API 适配、路由守卫、错误处理和关键组件；Playwright 覆盖登录、日记、聊天、知识发布与 RBAC。
6. CI 门禁：前端 lint/test/build，后端 test/package，迁移校验，OpenAPI diff 和依赖扫描。

## 6. 下一轮建议

优先建立可重复的测试环境和 P0 权限测试，再处理 JWT 撤销/刷新、协议异常映射和前端日志/拆包。做到这些后，才适合进入真实模型接入和预发布演练。
