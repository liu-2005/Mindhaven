# 模型输出安全与会话恢复修复

## 输出安全

回复、情绪解释、建议及行动项在发布前统一检查：本地规则预检，再由 DeepSeek 独立 JSON 审核。检查覆盖危险操作、诊断与药物建议、虚假专业身份、依赖诱导和敏感信息索取。审核拒绝、超时或结果格式异常均返回固定安全提示；被拒绝的原文不保存到消息或恢复快照，也不通过 SSE 发出。

模型输出事件使用 OUTPUT_BLOCKED 单独标识，不因此提高用户情绪风险。情绪建议被拦截时本轮评分不可用，避免展示未经审核的建议。已由本地识别的高风险输入直接使用固定指引，不依赖外部模型。

正常对话通常增加一次模型审核调用，加上回复与情绪分析共三次调用，会增加延迟和费用。这些检查是工程防线，尚不能替代完整安全评测、误报漏报评估和专业人员验收。

## 数据一致性与恢复

新增 V5 迁移和 mh_chat_turn 表。请求经过 GENERATING → PREPARED → COMPLETED：

1. 按会话锁定并检查请求 ID 与消息摘要，生成任务使用五分钟租约，防止同一会话并发生成。
2. 将审核后的回复和分析保存为 PREPARED 检查点。
3. 助手消息、情绪分析、会话计数、风险事件以及 COMPLETED 状态在同一事务提交；失败全部回滚，保留检查点。
4. 事务提交后才向浏览器发送回复。相同请求 ID 的重试复用已保存结果，不再次生成。

后台默认每 30 秒扫描最多 20 条 PREPARED 记录，重试数据库保存，不调用模型。可通过 app.chat.recovery.enabled 和 app.chat.recovery.delay-ms 配置。删除会话时同时清理检查点；既有最小风险事件保留策略不变。

保证边界：检查点成功持久化后，恢复无需重新调用模型。如果进程在收到上游回复后、检查点提交前退出，重试仍可能重复调用并计费。限流仍使用单实例内存计数；这些改动不代表完成全部分布式部署保障。

## 验证结果

- 后端 43 项测试通过，包括独立审核协议、审核失败关闭、危险回复拦截、真实事务回滚、风险写入失败、计数写入失败、恢复与幂等重试。
- 前端生产构建通过；仍有大包警告。
- 后端已重启，本机 MySQL 新检查点表可用；使用本地规则接管的虚构文本完成保存与相同请求重试，只产生两条消息，临时会话已删除。保留最小化测试风险事件。
- 本机接口脚本 8 组检查通过，覆盖权限、日记、会话、文件、隐私确认、凭证轮换与退出。
- 本轮安全异常测试使用模拟模型；没有向外部服务发送上述测试对话，未开展大规模模型安全评测或生产灾难恢复演练。

当前两项主要缺陷已有代码和验证支撑；隐私全生命周期、敏感数据访问审计完整性以及生产部署验收仍需继续完成。
