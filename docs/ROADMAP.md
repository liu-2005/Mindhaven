# MindHaven 交付路线图

最新交付与剩余缺口见 [2026-10-21 完善记录](./IMPROVEMENTS_2026-10-21.md)；下方为2026-08-03路线图快照。

> 版本：v0.2 · 2026-08-03
> 本路线图按依赖和风险排序，不代表已经承诺具体日历日期。

## 1. 当前阶段结论

项目已完成主要前后端功能的本地 MVP 闭环，M0-M3 的“主路径实现”大体存在，但各里程碑的测试、安全和运维退出条件均未完全满足。下一步重点不是继续扩功能，而是补自动化测试、协议/权限边界、令牌生命周期、真实模型安全和生产工程化。

| 里程碑 | 主路径实现 | 退出条件 | 当前判断 |
| --- | --- | --- | --- |
| M0 基线与护栏 | 大部分完成 | OpenAPI、CI、完整测试基线缺失 | 进行中 |
| M1 账户/权限/审计 | 已实现 | 撤销/刷新、限流、越权测试缺失 | 进行中 |
| M2 日记/知识库 | 已实现 | E2E、文件安全和完整异常测试缺失 | 进行中 |
| M3 AI/危机安全 | 规则式本地版本已实现 | 真实模型、红队、危机演练缺失 | 进行中 |
| M4 运营与上线 | 聚合接口已实现 | 观测、恢复、隐私流程、预发布缺失 | 未完成 |

## 2. 里程碑

### M0：基线与工程护栏（P0）

目标：让团队围绕同一个产品、契约和质量标准开发。

- 评审 PRD、API、数据模型和管理员权限边界。
- 确定认证方案、模型供应商、数据保留和目标地区。
- 引入数据库迁移、全局异常处理、参数校验、OpenAPI、测试覆盖和 CI。
- 清理前端调试日志，移除角色自选和未实现的隐私/规模承诺。
- 建立环境配置、密钥管理与 `local/test/staging/prod` 约定。

退出条件：核心 ADR 已通过；CI 可构建前后端；数据库可从空库版本化创建；P0 契约可生成/校验。

### M1：账户、权限与审计（P0）

目标：形成可信的身份和授权边界。

- 注册、登录、退出、当前用户、密码哈希和登录限流。
- 服务端 RBAC、对象级授权与账户状态。
- 管理员账户通过受控方式创建，不能在前台注册或登录时自选。
- 记录角色变更、敏感查看和管理操作审计。
- 覆盖水平越权、垂直越权和令牌失效测试。

退出条件：普通用户无法进入任何管理接口；用户 A 无法访问用户 B 数据；安全测试通过。

### M2：日记与知识库闭环（P0）

目标：在不依赖 AI 的情况下形成可用首版。

- 用户日记新建、列表、详情、编辑、删除和 7/30 天趋势。
- 分类、文章草稿/发布/下线、公开列表详情和稳定阅读统计。
- 富文本清洗、文件校验、私有存储与孤儿文件清理。
- 统一评分范围、分页结构、状态枚举和空/错态体验。

退出条件：两个纵向模块通过 API、权限、数据库迁移和前端 E2E 验收。

### M3：AI 会话与危机安全（P0）

目标：交付可控、可追踪、可降级的 AI 陪伴。

- 会话/消息生命周期、稳定 SSE 协议、幂等与断连处理。
- 模型适配器、提示词版本、超时重试、成本与额度控制。
- 输入/输出风险检查、固定安全指引、风险事件落库和处置工作台。
- 明确非医疗声明、数据用途、模型供应商边界和地区化求助信息。
- 完成红队测试、危机演练和上游故障降级测试。

退出条件：普通/边界/危机用例均有自动化与人工验收证据；风险提示不依赖模型可用性。

### M4：运营分析与上线准备（P1）

目标：让系统可运营、可观察、可恢复。

- 用后端聚合接口替换浏览器拉取 500 条记录计算看板。
- 指标、结构化脱敏日志、追踪、告警与容量基线。
- 用户数据导出/注销、数据清理、备份恢复和密钥轮换流程。
- 可访问性、移动端、性能、兼容性和安全回归。
- 预发布灰度、值班与事故响应手册。

退出条件：PRD 上线门槛全部完成并由产品、研发、测试、安全共同确认。

## 3. 优先级清单

### 立即处理

- 为认证、所有权、RBAC、迁移和 SSE 建立可重复的集成测试；前端加入 lint/test/E2E。
- 补服务端令牌撤销/刷新与登录限流，移除默认密钥进入非本地环境的可能。
- 修正协议异常映射（例如不支持的 `Content-Type` 不应返回 500）。
- 产出 OpenAPI v1，统一 ID、时间、分页和枚举的实际序列化约定。
- 确定危机处置责任、地区化文案、敏感访问理由和数据保留期限。
- 清理前端调试日志，并对超过 500 kB 的构建 chunk 拆包。

### 随核心功能交付

- 对话幂等、限流、超时和 SSE 稳定协议。
- HTML 清洗、文件存储、病毒/类型/大小校验。
- 审计、日志脱敏、对象级授权自动化测试。
- 聚合统计 API 和指标口径。

### 后续增强

- 个性化内容推荐、日记提醒、多维趋势。
- 搜索服务、异步事件管道、多实例缓存。
- 在明确专业资质、责任和隐私方案后再评估真人咨询能力。

## 4. 风险登记

| 风险 | 概率/影响 | 当前迹象 | 缓解措施 |
| --- | --- | --- | --- |
| 管理员越权 | 高/严重 | 登录角色由前端选择，本地守卫授权 | M1 前禁止对外；服务端 RBAC + 越权测试 |
| 心理危机漏报/误导 | 中高/严重 | 仅比较两个中文标签，无独立安全链路 | 稳定枚举、双重检查、固定指引、演练与人工流程 |
| 隐私泄露 | 高/严重 | localStorage 令牌、调试日志、管理端原文 | 认证 ADR、日志清理、最小权限、敏感访问审计 |
| 接口返工 | 高/中 | 多路径、多分页名、多字段别名 | 先冻结 OpenAPI，契约测试，删除前端猜测逻辑 |
| XSS/恶意文件 | 中高/高 | `v-html` 与上传流程已在原型中 | HTML 白名单、CSP、文件头/类型/大小校验、私有存储 |
| 指标错误 | 高/中 | 前端最多取 500 条后聚合 | 后端聚合接口、数据字典、抽样对账 |
| 模型成本/不稳定 | 中高/高 | 尚无限流、幂等和降级 | 配额、缓存/摘要、超时、熔断、供应商适配层 |
| 技术栈与依赖风险 | 中/中 | 新版框架组合，当前测试极少 | 锁定版本、依赖扫描、集成测试、升级节奏 |

## 5. 每项需求的完成定义

一项功能只有同时满足以下条件才算完成：

- PRD 验收条件明确且已通过。
- API/OpenAPI、数据模型和迁移脚本同步。
- 成功、错误、空数据、超时、重复提交和权限路径均有处理。
- 单元/集成测试通过；P0 具备前端 E2E 或等效证据。
- 日志不包含密码、令牌、完整日记或完整对话。
- 指标、告警、运维说明和回滚方式已补齐。
- 文档与实际界面文案一致，未承诺尚未实现的能力。

## 6. 建议的首批研发任务

1. `test: Testcontainers + MockMvc 覆盖迁移、认证、RBAC 与对象级授权`
2. `test: SSE 幂等、断连、UTF-8 分片、危机与超时场景`
3. `auth: 实现可撤销会话/刷新轮换与登录限流`
4. `api: 修复 415/400 等协议异常映射并生成 OpenAPI v1`
5. `frontend: 引入 ESLint/Vitest/Playwright，清理调试日志和拆分大 chunk`
6. `file/security: 文件头校验、授权下载、CSP 与富文本清洗回归`
7. `safety: 地区化危机指引、敏感访问理由、处置 SLA 与演练`
8. `data: 权限集合去重、阅读统计口径与数据生命周期迁移`
9. `ops: 建立 CI、依赖扫描、结构化脱敏日志、指标和告警`
10. `release: 备份恢复、密钥轮换、预发布与回滚演练`
