# 心晴 MindHaven 产品需求文档（PRD）

> 版本：v0.1  
> 状态：评审基线  
> 更新日期：2026-08-01

## 1. 产品概述

MindHaven 是面向成年普通用户的情绪自助与心理健康科普产品。它通过情绪日记、AI 陪伴式对话、情绪趋势和知识文章，帮助用户记录感受、提升自我觉察，并在识别到高风险表达时引导用户寻求现实世界的支持。

产品不是医疗服务、心理诊断工具或紧急救援渠道，AI 回复不得冒充心理咨询师、医生或作出诊断、处方和疗效承诺。

## 2. 问题与目标

### 2.1 用户问题

- 情绪发生时缺少低门槛、可持续的记录工具。
- 用户很难从零散记录中发现情绪、睡眠、压力和事件之间的关系。
- 有倾诉需求时，现实中的支持不一定能即时获得。
- 心理健康信息质量参差，用户需要结构化、可审阅的科普内容。

### 2.2 首版目标

- 让用户在 3 分钟内完成一篇情绪日记。
- 让登录用户能够创建、继续和回看 AI 陪伴会话。
- 让用户看到可解释的情绪分析和明确的非医疗边界。
- 让管理员安全地运营文章、查看聚合指标并处理风险事件。
- 建立认证授权、隐私与危机处置的最小安全闭环。

### 2.3 非目标

- 不提供疾病诊断、治疗方案、药物建议或替代专业服务。
- 首版不开放真人咨询师撮合、付费咨询、社区互动和未成年人服务。
- 首版不根据单次情绪评分自动联系外部机构或亲友。
- 管理员不能以运营便利为由任意浏览普通用户的完整隐私内容。

## 3. 用户与权限

| 角色 | 核心诉求 | 权限边界 |
| --- | --- | --- |
| 访客 | 了解产品、阅读公开科普 | 仅访问首页、注册登录、已发布文章 |
| 注册用户 | 写日记、AI 对话、回看个人数据 | 仅访问和管理自己的数据 |
| 内容管理员 | 维护知识内容 | 文章分类与文章管理，不默认查看用户隐私 |
| 安全/运营管理员 | 处理风险、查看聚合运营数据 | 按最小权限访问，所有敏感操作留审计 |
| 系统服务 | 执行分析、模型调用、异步任务 | 使用服务身份，不模拟用户或管理员 |

管理员角色必须由服务端账户或授权流程授予。登录页面不能允许用户自行选择管理员身份，前端 `userType` 也不能作为授权依据。

## 4. 核心用户旅程

### 4.1 首次使用

访客了解产品 → 阅读隐私说明与 AI 使用边界 → 注册 → 登录 → 进入日记或 AI 会话 → 获得首次反馈。

### 4.2 情绪日记

用户选择日期、1–10 心情分、主要情绪 → 填写触发因素与感想 → 记录 1–5 级睡眠质量和压力水平 → 保存 → 查看历史和趋势 → 可编辑或删除自己的记录。

### 4.3 AI 陪伴

用户新建会话 → 系统展示边界与危机提示 → 用户发消息 → AI 以流式方式回复 → 系统持久化双方消息 → 更新会话级情绪分析 → 若触发风险规则，优先展示安全指引并生成风险事件。

### 4.4 知识阅读

访客/用户浏览已发布文章 → 按分类或关键词筛选 → 阅读详情 → 阅读量去重计数。管理员创建草稿、预览、发布、下线或归档文章。

### 4.5 风险处置

系统识别高风险表达 → 不继续普通建议流程 → 展示即时、清晰、因地区而异的求助指引 → 鼓励联系可信任的人和当地紧急服务 → 记录最小化风险事件 → 授权管理员按流程查看和标记处置状态。

## 5. 功能需求

### 5.1 账户与认证

| 编号 | 优先级 | 需求 | 验收要点 |
| --- | --- | --- | --- |
| FR-AUTH-001 | P0 | 用户使用用户名/邮箱和密码注册、登录、退出 | 密码加盐哈希；登录失败不泄露账户是否存在；退出后令牌失效 |
| FR-AUTH-002 | P0 | 服务端返回账户身份和权限 | 忽略客户端传入的角色；每个受保护接口执行服务端鉴权 |
| FR-AUTH-003 | P0 | 会话令牌安全管理 | 采用短期访问令牌或服务端会话；过期统一返回 401；禁止日志记录令牌 |
| FR-AUTH-004 | P1 | 个人资料查看和修改 | 用户只能修改自己的昵称、头像、手机号等允许字段 |
| FR-AUTH-005 | P1 | 密码重置 | 使用一次性、限时凭证；重置后旧会话失效 |

### 5.2 情绪日记

| 编号 | 优先级 | 需求 | 验收要点 |
| --- | --- | --- | --- |
| FR-DIARY-001 | P0 | 新建日记 | 日期必填且同一用户同一天默认最多一篇；评分 1–10；睡眠/压力 1–5 |
| FR-DIARY-002 | P0 | 查看个人日记列表和详情 | 支持分页、日期范围、情绪和评分筛选；不能读取他人记录 |
| FR-DIARY-003 | P0 | 编辑和删除个人日记 | 所有权校验；删除策略和保留周期明确；操作有确认 |
| FR-DIARY-004 | P1 | 展示趋势 | 至少支持 7/30 天平均分、记录数、主要情绪分布；空数据有解释 |
| FR-DIARY-005 | P1 | AI 分析 | 分析结果与原始日记分开存储，包含模型版本、生成状态和风险等级 |

### 5.3 AI 陪伴会话

| 编号 | 优先级 | 需求 | 验收要点 |
| --- | --- | --- | --- |
| FR-CHAT-001 | P0 | 创建、分页查看、打开和删除自己的会话 | 会话所有权由服务端校验；删除会话同步处理消息和分析记录 |
| FR-CHAT-002 | P0 | SSE 流式对话 | 事件类型固定为 `message`、`risk`、`done`、`error`；断开后可安全重试；消息不重复 |
| FR-CHAT-003 | P0 | 内容安全和危机分流 | 用户输入与模型输出都经过规则/模型检查；危机结果优先于普通回复 |
| FR-CHAT-004 | P0 | 会话情绪分析 | 返回 0–100 情绪分、标签、建议、改善行动、风险等级和说明；字段稳定 |
| FR-CHAT-005 | P1 | 会话标题与摘要 | 首轮后异步生成，用户可重命名；生成失败不影响聊天 |
| FR-CHAT-006 | P1 | 成本与滥用控制 | 用户级频率、并发、消息长度和每日额度限制；超限提示可理解 |

### 5.4 知识库

| 编号 | 优先级 | 需求 | 验收要点 |
| --- | --- | --- | --- |
| FR-KB-001 | P0 | 公开浏览已发布文章 | 未登录可访问；草稿/下线文章不可通过 ID 越权读取 |
| FR-KB-002 | P0 | 管理员维护文章 | 草稿、发布、下线状态流转；新增/编辑/删除均鉴权并审计 |
| FR-KB-003 | P0 | 分类管理 | 分类名称唯一、支持排序；被文章引用时不能直接硬删除 |
| FR-KB-004 | P0 | 安全富文本和图片 | 服务端清洗 HTML；限制文件类型、大小和路径；不信任客户端上传元数据 |
| FR-KB-005 | P1 | 搜索和推荐 | 支持标题/摘要/标签搜索；“热门”基于明确规则而非当前页前五条 |

### 5.5 管理后台与数据分析

| 编号 | 优先级 | 需求 | 验收要点 |
| --- | --- | --- | --- |
| FR-ADMIN-001 | P0 | 后台 RBAC | 角色至少拆分内容管理和安全运营；菜单隐藏不能替代接口鉴权 |
| FR-ADMIN-002 | P0 | 文章运营 | 对应知识库管理能力；操作记录管理员、时间、对象和结果 |
| FR-ADMIN-003 | P0 | 风险事件工作台 | 默认展示脱敏摘要；查看原文需额外权限和访问理由；支持状态流转 |
| FR-ADMIN-004 | P1 | 聚合看板 | 统计口径固定；查询由后端聚合接口完成，不从 500 条列表在浏览器估算 |
| FR-ADMIN-005 | P1 | 数据导出 | 默认不导出对话/日记原文；敏感导出需要审批、审计和水印 |

### 5.6 隐私与用户控制

| 编号 | 优先级 | 需求 | 验收要点 |
| --- | --- | --- | --- |
| FR-PRIV-001 | P0 | 明示告知与同意 | 注册前可查看隐私说明、AI 数据用途、保存期限和危机边界 |
| FR-PRIV-002 | P0 | 数据最小化 | 仅收集功能必需数据；日志、监控和提示词中避免写入完整敏感内容 |
| FR-PRIV-003 | P1 | 数据导出与注销 | 用户可申请导出自己的数据并注销；后台任务可追踪、可重试 |
| FR-PRIV-004 | P1 | 模型数据控制 | 明确第三方模型处理范围；默认禁止供应商使用内容训练（如供应商能力支持） |

## 6. 业务规则

- 心情评分范围为 1–10；睡眠质量和压力水平统一为 1–5。现有管理端显示 `/10` 的地方需在实现时修正。
- 文章状态统一为：`DRAFT`、`PUBLISHED`、`OFFLINE`、`ARCHIVED`。客户端可展示中文，接口不再使用含义不直观的裸数字。
- 风险等级统一为：`NORMAL`、`CONCERN`、`WARNING`、`CRISIS`，不能仅依赖“极度危险”等展示文案触发处置。
- AI 情绪分表达模型判断强度，不等同临床量表分数；界面必须说明其局限。
- 文章阅读数、会话数、活跃用户等指标必须在数据字典中定义统计窗口与去重规则。

## 7. 非功能需求

| 编号 | 领域 | 目标 |
| --- | --- | --- |
| NFR-SEC-001 | 安全 | OWASP 常见风险基线；密码强哈希；RBAC；对象级授权；富文本清洗；上传校验；敏感配置只来自安全配置源 |
| NFR-PRIV-001 | 隐私 | 传输使用 TLS；数据库、备份和对象存储具备静态加密；日志脱敏；最小权限访问 |
| NFR-SAFE-001 | 心理安全 | 危机链路可独立降级；安全提示不被普通模型输出覆盖；规则和文案可配置、可审计 |
| NFR-PERF-001 | 性能 | 普通 API P95 < 500 ms；首个 SSE 内容 P95 < 3 s（不含上游模型故障） |
| NFR-REL-001 | 可靠性 | 核心 API 月可用性目标 99.9%；模型失败有明确降级；写操作使用幂等或重复提交保护 |
| NFR-OBS-001 | 可观测性 | 请求 ID、结构化日志、指标和告警；禁止采集密码、令牌、完整日记和完整对话 |
| NFR-A11Y-001 | 可访问性 | 键盘可操作、表单错误可读、颜色不是唯一状态表达、移动端关键流程可用 |
| NFR-COMP-001 | 兼容性 | 支持近期主流桌面与移动浏览器；API 版本化并保留兼容窗口 |

## 8. 成功指标

首版上线前先建立埋点与口径，避免使用首页当前的 `10w+`、`500+` 等无数据支撑文案。

| 指标 | 定义 | 首版观察目标 |
| --- | --- | --- |
| 激活率 | 注册后 24 小时内完成首篇日记或首个有效会话的用户占比 | 建立基线后设目标 |
| 7 日留存 | 新用户第 7 日仍有日记或会话行为 | 建立基线后设目标 |
| 日记完成率 | 打开日记页后成功保存的会话占比 | ≥ 70%（试运行目标） |
| AI 有效回复率 | 成功产生非空、通过安全检查的回复占比 | ≥ 98%（不含用户主动断开） |
| 风险链路成功率 | CRISIS 事件完整展示安全提示并落库的占比 | 100% |
| 越权缺陷数 | 测试或生产发现的对象级/角色级越权 | 0 |

## 9. 上线验收门槛

- P0 需求全部通过功能、权限和异常路径测试。
- 完成用户 A 读取/修改用户 B 数据的系统性越权测试。
- 完成 AI 输入输出安全测试和危机场景演练，确认模型不可覆盖固定安全提示。
- 首页、注册页、对话页展示准确的隐私与非医疗声明，删除尚未实现的营销承诺。
- 数据库迁移、备份恢复、密钥轮换、日志脱敏和告警演练通过。
- 产品、研发、测试和安全负责人共同签署上线检查表。

## 10. 待产品确认

- 首版目标地区与适用法律、热线和紧急服务文案。
- 是否限制为 18 岁以上用户；若支持未成年人，需要独立的监护与安全方案。
- 数据保存期限、软删除宽限期和注销后的法定保留范围。
- AI 模型供应商、部署方式、内容是否跨境、成本上限和降级策略。
- 管理员是否允许查看原始日记/对话；如允许，具体审批和审计流程。
